# RicoPalette

早稲田大学 西早稲田（理工）キャンパスを3Dで再現し、複数の世界に切り替えて歩けるWebGLアプリです。Three.js で作成しました。

実際のキャンパスモデル（`rikocamtex.glb`）を舞台に、Urban / Nature / CyberPunk / Underwater / Universe と隠しシーンを、画面上のボタンで切り替えながら一人称で歩き回れます。「もし理工キャンパスが〇〇だったら（What if Rico were in 〇〇）」をコンセプトに、同じ空間をシーンごとに違う見た目や動きで表現しています。

## Requirements

- Node.js
- npm（Node.js に同梱）

未インストールの場合は [nodejs.org](https://nodejs.org/ja) か Homebrew（`brew install node`）等で Node.js を導入してください。

## How to Run

1. 依存関係をインストール:

   ```bash
   npm install
   ```

2. 開発サーバーを起動:

   ```bash
   npm run dev
   ```

3. ターミナルに表示されたURL（通常は `http://localhost:5173`）を開く。

## アーキテクチャ

6つのシーンは、見た目も物理もライティングも異なります。これを1つのコードベースで管理し、シーンを増やしやすくするために、各シーンを共通インターフェース（`BaseEnvironment`）でまとめ、`EnvironmentManager` が現在のシーンを State パターンで切り替える構成にしています。

```
EnvironmentManager (Singleton / 現在のシーンを一元管理)
        │  switchMode(name)
        ▼
BaseEnvironment ── init() / update() / dispose() / onKeyDown() ...
        ├─ UnderwaterEnvironment
        ├─ CyberPunkEnvironment
        ├─ UniverseEnvironment
        └─ ...
```

新しいシーンを追加するときに既存のシーンを触らずに済み、チームで別々のシーンを並行して開発できます。シーンの切り替え時にはリソースを `dispose()` で明示的に破棄し、建物モデルや手続き生成したテクスチャなどの共有アセットはキャッシュから再利用することで、メモリの使用量とロード時間を抑えています。

## 各シーンの実装

### 🏙️ Urban

建物の壁・窓・屋根を、マテリアル名に応じてそれぞれ専用の GLSL シェーダーで描画しています。テクスチャ画像ではなくシェーダーで陰影や窓の格子を表現しているため、同じ建物モデルに対してシェーダーだけを差し替えれば、Nature など他のシーンでも見た目を変えて使い回せます。

### 🌿 Nature

木は L-System（Lindenmayer System）で生成しています。木を1本ずつモデリングする代わりに、生成規則から枝分かれの構造を作り、タートルグラフィックスで幹のジオメトリと枝先の位置を求めています。すべての木を個別に生成・描画すると重くなるため、5種類のテンプレートをあらかじめ生成し、幹と葉（枝先に置いた球）をそれぞれ `InstancedMesh` でまとめて描画することで、本数を増やしても負荷を抑えられるようにしました。地面には草地表現のシェーダーを適用しています。

### 🤖 CyberPunk

質感をテクスチャ画像ではなく手続き的に生成しています。Reaction-Diffusion、Voronoi、SDF（符号付き距離場）、FBMノイズといった複数のシェーダーを用意し、シーンに散らした多数のオブジェクトに適用しています。画像を用意しなくてもシェーダーのパラメータだけで見た目の異なるオブジェクトを増やせるため、アセット容量を抑えつつ密度のある空間を作れます。さらに、L-System で生成した構造物を建物の壁面や屋上から生やし、Synthwave風のグラデーション背景と組み合わせています。

### 🌊 Underwater

2,500匹以上の魚に群れ（Boid）の動きをさせています。各個体が近くの仲間を毎フレーム探す必要があり、総当たりでは計算量が O(N²) になります。2,500匹では1フレームあたり600万回以上の距離判定が必要で、実用的ではありません。

Octree や kd-tree も検討しましたが、魚は毎フレーム全個体が動くため、木構造ではフレームごとの再構築コストが大きくなります。一方で、魚の分布はほぼ一様で、セルサイズを知覚半径に合わせられます。これらを考慮して、毎フレーム O(N) で作り直せる一様グリッドと連結リスト法を採用しました。各個体は自分のいるセルとその周囲3×3×3のセルだけを調べればよく、走査する対象が一定数に収まります。障害物回避も同様に、まず軸ごとの距離とバウンディング半径で候補を絞り、残ったものだけ正確な二乗距離とレイキャストで判定する二段階にしています。

描画では、各個体を個別の `Mesh` にすると描画命令（ドローコール）が個体数だけ増えるため、`InstancedMesh` で1回の描画命令にまとめています。尾びれの揺れ、遊泳速度、大きさといった個体差は、頂点属性（`InstancedBufferAttribute`）と頂点シェーダーで表現しています。負荷の高い場面では、Caustics や God Rays の計算を必要な範囲に省略しました。

### 🌌 Universe

星空と星雲を、静止画像ではなく手続き的に生成しています。方向ベクトルから3Dノイズ（FBM）をサンプリングして CubeMap の各面を描くことで、6面の境界でも模様が途切れずにつながるようにしています。生成にはシード付きの乱数を使い、毎回同じ星空が得られるようにしました。生成のコストが高いため、一度作った CubeMap は共有アセットとしてキャッシュし、次に同じシーンへ入ったときは再利用します。建物は宇宙向けのシェーダーで描画しています。

### ❓ ???

レーザーが当たった面をその場で切り出し、破片として飛散させます。破片の動きは、初速で飛散し、重力で落下し、自転するという決まった放物運動です。この点を考慮して、経過時間（`uTime`）から頂点位置を計算する方式を採用しました。CPU側は着弾面を分離してジオメトリを一度作るだけで、その後の毎フレームの動きは頂点シェーダーが計算します。落下しきった破片はシェーダー内で表示を消し、一定時間後に CPU でまとめて破棄します。

## パフォーマンスの調整

`lil-gui` でパラメータを実行中に変更できるようにし、魚2,500匹などの重いシーンでフレームレートを見ながら、セルサイズや走査範囲、省略してよいシェーダーの計算を調整しました。

## 技術スタック

- Three.js（WebGL） / カスタム GLSL シェーダー（`vite-plugin-glsl`）
- Vite（開発サーバー・ビルド）
- lil-gui（パラメータ調整）

チーム開発です。State パターンで各シーンを疎結合にすることで、メンバーが別々のシーンを並行して実装できるようにしました。シェーダーの定型的な記述やリファクタリングの一部では生成AIを補助的に使っていますが、どのアルゴリズムを選ぶかや設計の判断は自分たちで行っています。
